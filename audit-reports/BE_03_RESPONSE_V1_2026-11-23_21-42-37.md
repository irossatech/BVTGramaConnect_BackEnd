## In short

The database and query audit found **27 issues** (High 2, Medium 12, Low 9, Info 4). This is where each one stands:

| Result | How many |
|---|---|
| ✅ Fixed | 19 |
| 🟡 Partly fixed (what is left is explained) | 5 |
| ⚪ Not changed on purpose (the reason is given) | 2 |
| ⏳ Later: needs the server database or the production team | 1 |

**Both High issues are dealt with.** The dashboard and reports now count in the database with a few queries per page,
whatever the number of districts (BE-DB-001). The audit log counts once per page and its export reads only the columns
it writes (BE-DB-002); what is left there is search speed on a very large log, to measure on real data.

**Testing.** Every fix came with tests, many of them query-count tests that fail if a query per row comes back.
The whole suite on `dev` on 2026-11-23: **3,473 passed, 9 skipped, 0 failed**. No database change is missing
(`makemigrations --check`).

**Decisions made after the audit that change some answers.**
- 2026-11-14: data is kept permanently (lead's decision). This answers BE-DB-018.
- 2026-11-20: nothing is hidden by age (owner's decision). The 90- and 180-day windows added for BE-DB-002 and
  BE-DB-018 were removed again; lists show every record, page by page.
- 2026-11-20: the per-IP limits were removed (lead's decision, deferred until before going live). This leaves the
  "throttle anonymous searches" part of BE-DB-009 open.
- 2026-11-21: a citizen block no longer discards posts. This makes BE-DB-023 moot; the fix stays.

## High

**BE-DB-001: dashboard and reports query per area and aggregate in Python** ✅ Fixed
- **Problem:** the console dashboard and reports asked the database once per district and once per mandal, added
  the numbers up in Python and paged in Python. `posts-by-area` and its CSV export grew with the number of mandals.
- **What we did:** the dashboard and reports count per area in the database (`a944abb`), and the admin-activity
  report counts and pages in the database (`dd69460`). Query-count tests keep it that way
  (`apps/web_admin/tests/test_report_queries.py`, `test_admin_activity_paging.py`).

**BE-DB-002: the audit log list and export do not scale** 🟡 Partly fixed
- **Problem:** every audit page ran a `COUNT(*)` and a second `GROUP BY` count, text search used four "contains"
  filters, and the export loaded up to 50,000 full rows, JSON included, into memory.
- **What we did:**
  - The page total now comes from the per-type counts, so the table is counted once per page (`29f84b4`).
  - The export reads only the nine columns it writes, in chunks. Over 50,000 rows it is refused with "Choose a
    shorter date range" instead of a cut file.
  - A default date window was added (`c3e1044`) and later removed on purpose: since 2026-11-20 nothing is hidden by
    age (owner's decision).
- **Left:** pages are still numbered (OFFSET), and search still uses "contains". Measure on real data (with BE-PERF-007
  of BE_01 and BE_02) before changing either.

## Medium

**BE-DB-003: notification fan-out runs several queries per recipient** ✅ Fixed
- Each notification text and area is read once for all recipients, and inbox items are written in one INSERT
  (`abef1c3`, with BE_01 PR 4). A test proves 21 officials cost the same as 1.

**BE-DB-004: the Super Admin "never zero" and "at most N" rules could break under simultaneous changes** ✅ Fixed
- Super Admin changes are now serialised and checked again inside the transaction (`803ce3d`,
  `apps/accounts/tests/test_super_admin_race.py`).

**BE-DB-005: the citizen summary costs 3 queries per citizen post** ✅ Fixed
- The summaries for a whole page come from two queries (`49fd09c`, `apps/citizens/tests/test_phone_summary.py`).

**BE-DB-006: service-request `allowed_actions` loads rights per row** ✅ Fixed
- Rights are checked once per page, not per row (`b88142c`, `apps/service_requests/tests/test_list_queries.py`).

**BE-DB-007: list orders without matching indexes; one stale Post index** ✅ Fixed
- New indexes on Post (`created_at`), Post (`status`, `published_at`) and ServiceRequest (`updated_at`); the unused
  Post index was removed (`a608a09`, migrations posts 0010 and service_requests 0007, reversible, no data change).

**BE-DB-008: the feed's media count turns every page into a GROUP BY** ✅ Fixed
- The feed counts each post's media without grouping every published post (`dce845c`,
  `apps/feed/tests/test_media_count.py`).

**BE-DB-009: several counts per page, and unindexed text search** 🟡 Partly fixed
- **What we did:** the posts list, the review queue and the service requests count once per page (`a1a0e2e`).
- **Left:** "contains" search is unchanged; measure on real data first. Limiting anonymous searches per address is
  part of the per-IP limits removed on 2026-11-20, deferred until before going live.

**BE-DB-013: deploys migrate with no backup first** 🟡 Partly fixed
- **What we did:** both deploy scripts take a database backup before migrating, and the qa deploy backs up before
  pulling the new code (`ddb0a33`, `11bf9e6`). The conventions keep schema changes and data steps in separate
  migrations, so a failure leaves less half done on MySQL.
- **Left:** a RUNBOOK section on recovering from a half-applied migration on MySQL (restore the backup taken just
  before).

**BE-DB-014: count-then-insert limits and check-then-insert uniqueness** 🟡 Partly fixed
- **What we did:** citizen posts and service requests per day are counted again inside the transaction with the
  phone's installs locked; important numbers per area lock the area row; a username or mobile taken at the same moment
  answers `409 duplicate`; a service or bill key taken at the same moment gets the next free key (`184dd5c`, `68c9c32`).
- **Left:** the photo limit (3 per post) is still counted before the upload is saved (`apps/posts/media.py`), so two
  uploads at the very same moment could add a fourth photo. Only the post's author uploads to it, so this is rare.

**BE-DB-016: the escalation run is unbatched and sends alerts inside it** ✅ Fixed
- The escalation job runs in bounded batches, and each alert is a job of its own (`6dc6d3c`,
  `apps/posts/tests/test_escalation_batches.py`).

**BE-DB-018: no retention for most user-driven tables** ⚪ Not changed, on purpose
- **Why:** data is kept permanently (lead's decision of 2026-11-14): contact messages, service requests, citizen
  phone records, posts and the audit log are never deleted.
- **What is cleaned up:** expired sessions and tokens, failed background jobs, old failed-login records, and officials'
  read notifications after 90 days (`a0930d7`, `NOTIFICATION_KEEP_DAYS`).

**BE-DB-021: engine differences the SQLite-only tests cannot catch** 🟡 Partly fixed
- **What we did:** the two differences code could fix without knowing the server database (`209db8e`): the dashboard
  read the escalation hours under a name only MySQL's collation matched, and the Telugu duplicate-name check now
  compares in Python, because MySQL's collation can treat some Telugu vowel signs as equal. Tests in
  `grama/tests/test_engine_differences.py`.
- **Left:** one CI job on the server database, once the owner chooses MySQL or PostgreSQL (Jira BVTGC-38).

## Low

**BE-DB-010: MySQL `sql_mode` narrowed to `STRICT_TRANS_TABLES`** ✅ Fixed
- MySQL and MariaDB now use strict `TRADITIONAL,ONLY_FULL_GROUP_BY` (`186cf4a`).

**BE-DB-011: qa runs threaded runserver with persistent connections** ✅ Fixed
- qa closes database connections after each request (`ddb0a33`).

**BE-DB-015: media files written inside database transactions** ✅ Fixed
- No media file is left on disk without its row, and deleting a draft deletes its video too (`b07dd2b`,
  `apps/posts/tests/test_media_cleanup.py`).

**BE-DB-017: the job broker polls 5 times a second when idle** ✅ Fixed
- It polls once a second (`b48a206`, `grama/tests/test_queue_poll.py`).

**BE-DB-019: housekeeping deletes in single statements** ✅ Fixed
- Housekeeping deletes in batches (`7198660`, `grama/tests/test_housekeeping_batches.py`).

**BE-DB-020: random share codes and MySQL's case-insensitive collation** ✅ Fixed
- Share codes work the same on every database (`9aaa012`, `apps/share/tests/test_share_code_any_database.py`).

**BE-DB-022: small race windows** ✅ Fixed
- Refresh token, service-request status and schedules (`cc31217`, `grama/tests/test_small_races.py`).

**BE-DB-023: multi-row admin actions not atomic as a whole** ✅ Fixed
- Blocking a phone and discarding its posts happened together (`5c4ee58`). Since 2026-11-21 a block discards nothing
  ("Discard all" is a separate action), so this case no longer arises.

**BE-DB-024: irreversible data migrations, and per-row data steps** ✅ Fixed (for new migrations)
- Merged migrations stay as they are (project rule). The conventions now require a reverse step or "irreversible" in
  the pull request, batches, and schema changes apart from data steps (`13f4096`, `.claude/conventions.md`).
